Guide · GitHub Pages

Déployer un site multi-pages
sur GitHub, sans .github.io

La marche à suivre claire, plus les prompts prêts à copier-coller pour faire créer tout ça automatiquement. À transmettre tel quel à ton ingénieur.

1 D'où vient le /cnc/ dans l'adresse

GitHub Pages fabrique l'URL à partir du nom du dépôt. Il existe 3 cas — c'est toute la clé.

Cas actuel de Seb

Project page

pseudo.github.io/cnc/
Le /cnc/ = le nom du repo. Un repo par site. Le plus simple, c'est ce que tu as déjà.
Enlève le /nom/

User page

pseudo.github.io/
Nomme le repo exactement pseudo.github.io. Servi à la racine, sans dossier. Un seul par compte.
Sans .github.io

Domaine perso ★

monsite.com
Un nom de domaine acheté (~10 €/an) branché sur GitHub. Plus aucun .github.io. HTTPS gratuit inclus.
Bonus

Plusieurs pages

/ · /contact.html · /blog/
Chaque fichier .html = une URL. Un dossier avec un index.html = une jolie URL propre.

2 La marche à suivre

A · Un site auto-déployé en 5 étapes

  1. Créer le dépôt sur GitHub (bouton New repository). Public.
  2. Ajouter les fichiers : au minimum un index.html.
  3. Activer Pages : Settings → Pages → Source = Deploy from a branch → branche main, dossier /root.
  4. Attendre ~1 min : le site est en ligne sur pseudo.github.io/nom-du-repo/.
  5. Déploiement auto : désormais chaque git push sur main met le site à jour tout seul.

B · Structure conseillée pour du multi-pages

mon-site/ ├── index.html # page d'accueil → monsite.com/ ├── contact.html # → monsite.com/contact.html ├── blog/ │ └── index.html # → monsite.com/blog/ ├── assets/ │ ├── style.css # styles partagés │ └── logo.svg └── CNAME # contient : monsite.com (pour le domaine perso)
Astuce propre : mets chaque section dans son dossier avec un index.html dedans → tu obtiens /blog/ au lieu de /blog.html. Plus classe et plus facile à retenir.

C · Supprimer le .github.io (domaine perso)

  1. Acheter un domaine chez OVH, Gandi ou Namecheap (~10 €/an).
  2. GitHub : Settings → Pages → Custom domain → taper monsite.com → Save. Ça crée le fichier CNAME.
  3. Chez le fournisseur de domaine : ajouter les enregistrements DNS de GitHub — un CNAME www → pseudo.github.io, et 4 A vers les IP de GitHub Pages.
  4. Cocher « Enforce HTTPS » dans GitHub une fois le DNS propagé (quelques minutes à quelques heures).
Important : les IP exactes des enregistrements A et la procédure DNS peuvent évoluer. Prends la liste à jour dans la doc officielle → docs.github.com · Custom domain.

3 Les prompts à me donner

Copie-colle ces prompts dans Cowork / Claude. Remplace juste les MOTS EN MAJUSCULES. Ils sont faits pour s'enchaîner.

① Créer le repo-modèleCrée-moi un site web statique multi-pages prêt pour GitHub Pages. Nom du projet : NOM-DU-SITE. Pages voulues : accueil, à propos, contact (ajoute/retire au besoin). Structure : un index.html à la racine, un dossier assets/ avec un style.css partagé, et chaque page secondaire dans son propre dossier avec un index.html dedans (pour avoir des URLs propres du type /contact/). Style : sobre et moderne, responsive, un menu de navigation identique sur toutes les pages. Tout en HTML/CSS pur, sans dépendance. Donne-moi les fichiers organisés.
② Ajouter une pageAjoute une nouvelle page « TITRE-DE-LA-PAGE » au site. Réutilise exactement le même en-tête, menu et pied de page que les autres pages, ajoute le lien dans le menu de navigation partout, et place-la dans son propre dossier avec un index.html pour l'URL /NOM-COURT/.
③ Préparer le déploiementPrépare ce site pour GitHub Pages : - vérifie que tous les liens entre pages et vers assets/ sont relatifs (pas d'URL en dur), - ajoute un fichier CNAME contenant : MONSITE.COM, - ajoute un fichier 404.html simple, - et donne-moi la liste exacte des étapes à faire côté GitHub (Settings → Pages) et côté DNS pour brancher mon domaine MONSITE.COM.
④ Mettre en ligne / mettre à jourPousse la dernière version du site sur le repo GitHub PSEUDO/NOM-DU-REPO, branche main, pour que GitHub Pages le redéploie automatiquement. Confirme-moi l'URL en ligne une fois que c'est poussé.
⑤ Débuguer un souciMon site GitHub Pages affiche PROBLÈME (ex : page blanche, CSS non chargé, domaine qui ne marche pas, vieille version en cache). Analyse la cause probable et corrige les fichiers concernés. Si c'est un souci de cache, ajoute les bonnes balises no-cache.
Le réflexe qui change tout : demande toujours « garde le même menu / en-tête / pied de page sur toutes les pages ». C'est ce qui fait qu'un multi-pages reste cohérent et propre au fil des ajouts.
